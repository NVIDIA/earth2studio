**Bases:** `Module`, [AutoModelMixin](../auto/mixin.mdx#earth2studio-models-auto-mixin-AutoModelMixin)

Climate Net diagnostic model, built into Earth2Studio. This model can be used to
create prediction labels for tropical cyclones and atmospheric rivers from a set of
three atmospheric variables on a quater degree resolution equirectangular grid. It
produces three non-standard output channels climnet_bg, climnet_tc and climnet_ar
representing background label, tropical cyclone and atmospheric river labels.

**Badges:** `region:global` `class:medium-range` `product:atmos` `year:2021` `gpu:40gb` `provider:nvidia` `backend:pytorch`

**Parameters:**

<ParamField path="core_model" type="torch.nn.Module">
Core pytorch model
</ParamField>

<ParamField path="center" type="torch.Tensor">
Model center normalization tensor of size [20,1,1]
</ParamField>

<ParamField path="scale" type="torch.Tensor">
Model scale normalization tensor of size [20,1,1]
</ParamField>

<Note>

This model and checkpoint are from Prabhat et al. 2021. For more information see the
following references:

- https://doi.org/10.5194/gmd-14-107-2021
- https://github.com/andregraubner/ClimateNet

</Note>

**Bases:** `Module`, [AutoModelMixin](../auto/mixin.mdx#earth2studio-models-auto-mixin-AutoModelMixin)

CorrDiff is a Corrector Diffusion model that learns mappings between
low- and high-resolution weather data with high fidelity. This model combines
regression and diffusion steps to generate high-resolution predictions.

**Badges:** `region:global` `class:downscaling` `product:wind` `product:precip` `product:temp` `product:atmos` `year:2023` `gpu:80gb` `provider:nvidia` `backend:pytorch`

Complete input preprocessing pipeline.

Performs interpolation to output grid, ensures a batch dimension,
concatenates invariants if available, and normalizes the input.

**Parameters:**

<ParamField path="x" type="torch.Tensor">
Input tensor of shape ``[C, H_in, W_in]`` or ``[B, C, H_in, W_in]``.
If a batch dimension is not present, one will be added.
</ParamField>

<ParamField path="valid_time" type="datetime | None" default="None">
Validity time for this sample (when the atmospheric state is valid).
The base class ignores this parameter. Subclasses can override this
method to compute time-dependent features such as solar zenith angle
(SZA). Default is None.
</ParamField>

**Returns:** `torch.Tensor`

Preprocessed and normalized input tensor ``[B, C+C_inv, H_out, W_out]``.

<Note>

For subclass implementers: ``valid_time`` is provided as an optional hook for
time-dependent preprocessing (e.g., solar zenith angle). The base
implementation ignores it; override this method if your model needs it.

</Note>

COSMO-REA downscaling model: ERA5 -&gt; high-resolution COSMO-REA.

Diagnostic model that downscales a global ERA5 state to high-resolution
COSMO-REA regional reanalysis over Europe -- COSMO-REA6 (~6 km) or COSMO-REA2
(~2.2 km), selected with ``resolution``. The input is an ERA5 state, so it can
downscale an ERA5 analysis directly or run behind a global forecast model
(e.g. SFNO -&gt; CorrDiffCosmoEra5).

``mode`` selects one of two networks trained per resolution:

* ``"mean"`` -- a deterministic regression predicting the conditional mean
  ``E[y | x]``: a single smooth field in one forward pass. Fast; a good first
  high-resolution look or a deterministic conditional-mean baseline.
* ``"diffusion"`` -- a generative model sampling the conditional distribution
  ``p(y | x)``: an ensemble of ``number_of_samples`` realizations (seeded for
  reproducibility) that also captures the spread the mean cannot represent.

Both networks are PhysicsNeMo DiTs at a fixed grid resolution but crop-size
agnostic, so `set_domain` returns an instance restricted to any lat/lon
sub-region without retraining (bounded to the trained footprint). Each
resolution ships an extended grid beyond its native footprint; for COSMO-REA2
-- whose native footprint is central-European -- the extended grid reaches a
broad European domain, enabling 2.2 km downscaling across it. Outputs are
surface and model-level (3D) fields -- winds,
temperature, humidity, precipitation, cloud cover, fluxes, TKE, PBL height;
variables with a canonical Earth2Studio name are relabelled via
[`CosmoLexicon`](../../lexicon/cosmo.mdx#earth2studio-lexicon-cosmo-CosmoLexicon) and COSMO-specific fields keep a
descriptive name. Optionally emits derived hub-height wind components (see
``hub_heights``).

**Badges:** `region:eu` `class:downscaling` `product:wind` `product:precip` `product:temp` `product:atmos` `year:2026` `gpu:80gb` `provider:nvidia` `backend:pytorch`

<Indent>

Restrict the model to a sub-domain for a lat/lon bounding box.

Returns a NEW `CorrDiffCosmoEra5` that shares the loaded network(s)
but whose target grid + static invariants are sliced to the smallest
block of the (rotated) grid covering ``[lat_min, lat_max] x [lon_min,
lon_max]``. The returned instance is a fixed-domain model with its own
``input_coords``/``output_coords``, so it composes with the standard run
pipelines. The ERA5 input grid is recomputed to cover it (+ ``margin_deg``).

The network is shared by reference and each forward rebinds its latent-grid
state on it in place, so the parent and its sub-domains are safe to run
sequentially but NOT concurrently against the same network (two threads or
async tasks would overwrite each other's grid binding -&gt; wrong-grid output);
run concurrent domains in separate processes.

Three-tier coverage (when the package ships extended invariants):

* bbox inside the **native** trained footprint -&gt; proceed (validated);
* bbox reaching into the **extended margin** (invariants exist there but
  it is outside the trained footprint) -&gt; proceed + a one-time OOD warning;
* bbox beyond the **extended extent** -&gt; ``ValueError`` (no invariants).

Without extended invariants only the native footprint is supported. A
returned sub-domain keeps only its own (cropped) grid, not the full or
extended one, so call ``set_domain`` once on the full loaded model: a
second ``set_domain`` on a returned sub-domain cannot reach back to the
full or extended footprint (a bbox outside the sub-domain's grid raises).
For several sub-regions, call ``set_domain`` multiple times on the full
model instead.

``halo`` (px, default 0 = off): run on a block expanded by ``halo`` real
cells per side and trim it off the output, keeping the returned bbox
interior clear of the DiT's boundary artifact (~32 px); clamps + warns at
the grid edge. Both models are DiT-RoPE (crop-size agnostic at the fixed
resolution), so any size runs in a single forward — but the run grid is
snapped to a multiple of
the DiT ``patch_size`` (an odd extent would floor to extent-1) and must be
at least ``attn_kernel*patch`` cells per side (NATTEN must fit the latent),
so very small bboxes raise.

</Indent>

Precipitation diagnostic for the DLESyMv0_ISCCP_ERA5 climate model.

A ``HEALPixUNet`` diagnostic from the AtmosSci-DLESM/DLESyM repository
that predicts 6-hourly accumulated precipitation (``tp06``) from the full
coupled atmosphere/ocean state. It is designed to be chained off
[`DLESyMv0_ISCCP_ERA5`](../px/dlesym_v0_isccp_era5.mdx#earth2studio-models-px-dlesym_v0_isccp_era5-DLESyMv0_ISCCP_ERA5) (or its lat/lon
variant).

The model takes 2 consecutive history timesteps of 10 variables (the 9
atmospheric variables plus ``sst``) on a HEALPix ``nside=64`` grid and
predicts ``tp06`` at the last input timestep (i.e., precipitation
accumulated over the 6 h prior to ``t=0``).

When ``use_ttr=True`` (default), the wrapper accepts ERA5 ``ttr`` in
place of ``rlut`` and applies the same per-doy moment-matching TTR -&gt; OLR
transform as
[`DLESyMv0_ISCCP_ERA5`](../px/dlesym_v0_isccp_era5.mdx#earth2studio-models-px-dlesym_v0_isccp_era5-DLESyMv0_ISCCP_ERA5)
before the forward pass. This allows the diagnostic to run standalone
from an ERA5 initial condition. When ``use_ttr=False``, supply
pre-transformed ``rlut`` directly -- use this when chaining off
[`DLESyMv0_ISCCP_ERA5`](../px/dlesym_v0_isccp_era5.mdx#earth2studio-models-px-dlesym_v0_isccp_era5-DLESyMv0_ISCCP_ERA5) output, which is
already in OLR space.

The derived inputs ``tp24``, ``t2m_max``, and ``t2m_min`` must be computed from
hourly ERA5 fields before calling the model:

&gt;&gt;&gt; import numpy as np
&gt;&gt;&gt; import torch
&gt;&gt;&gt; from earth2studio.data import NCAR_ERA5, prep_data_array
&gt;&gt;&gt; from earth2studio.models.dx import OrbitGlobalPrecip
&gt;&gt;&gt; from earth2studio.utils.time import to_time_array
&gt;&gt;&gt;
&gt;&gt;&gt; package = OrbitGlobalPrecip.load_default_package()
&gt;&gt;&gt; orbit = OrbitGlobalPrecip.load_model(package)
&gt;&gt;&gt; orbit = orbit.to("cuda")
&gt;&gt;&gt; data = NCAR_ERA5()
&gt;&gt;&gt; time = to_time_array([np.datetime64("2023-06-01")])
&gt;&gt;&gt;
&gt;&gt;&gt; # Fetch base variables (all except tp24, t2m_max, t2m_min)
&gt;&gt;&gt; base_vars = orbit.input_coords()`"variable"`
&gt;&gt;&gt; x, coords = prep_data_array(data(time, base_vars), device="cuda")
&gt;&gt;&gt;
&gt;&gt;&gt; # Build past 24-hour precipitation accumulation and t2 max/min.
&gt;&gt;&gt; batch_p = torch.zeros((len(time), 24, 4, x.shape[-2], x.shape[-1]), device="cuda")
&gt;&gt;&gt; for i in range(24):
...     time0 = np.array(time) - np.timedelta64(i, "h")
...     p, _ = prep_data_array(data(time0, ["cp", "lsp", "t2m", "sst"]), device="cuda")
...     batch_p[:, i] = p
&gt;&gt;&gt; total_p_24hr = (batch_p[:, :, 0] + batch_p[:, :, 1]).sum(dim=1).unsqueeze(1)
&gt;&gt;&gt; t2_sst_combined = torch.where(
...     torch.isnan(batch_p[:, :, 3]), batch_p[:, :, 2], batch_p[:, :, 3]
... )
&gt;&gt;&gt; t2_max = t2_sst_combined.max(dim=1).values.unsqueeze(1)
&gt;&gt;&gt; t2_min = t2_sst_combined.min(dim=1).values.unsqueeze(1)
&gt;&gt;&gt; x = torch.cat((x, total_p_24hr, t2_max, t2_min), dim=1)
&gt;&gt;&gt;
&gt;&gt;&gt; input_coords = OrderedDict(
...     &#123;k: v for k, v in orbit.input_coords().items() if k != "batch"&#125;
... )
&gt;&gt;&gt; input_coords["time"] = time
&gt;&gt;&gt; input_coords.move_to_end("time", last=False)
&gt;&gt;&gt; output, output_coords = orbit(x, input_coords)

**Bases:** `Module`, [AutoModelMixin](../auto/mixin.mdx#earth2studio-models-auto-mixin-AutoModelMixin)

Estimate Global Horizontal Irradiance from GOES imagery.

This diagnostic model is designed to be used with the
`earth2studio.models.px.StormScopeGOES` prognostic model, consuming
its GOES channel outputs to produce solar irradiance estimates.

A regression network produces a first estimate that is refined with a
warm-started diffusion sampler. Each requested sample is generated
independently at the input observation time.

**Example**

Using the diagnostic with forecasted GOES imagery from
`earth2studio.models.px.StormScopeGOES`. A
`earth2studio.data.GOES` data source can also be used directly
in place of the prognostic model output:

&gt;&gt;&gt; # Load StormScopeGOES prognostic and NSRDB diagnostic models
&gt;&gt;&gt; package = StormScopeBase.load_default_package()
&gt;&gt;&gt; goes_model = StormScopeGOES.load_model(package, conditioning_data_source=None)
&gt;&gt;&gt; goes_model = goes_model.to("cuda").eval()
&gt;&gt;&gt; nsrdb_model = StormScopeDxNSRDB.load_model(StormScopeDxNSRDB.load_default_package())
&gt;&gt;&gt; nsrdb_model = nsrdb_model.to("cuda")
&gt;&gt;&gt;
&gt;&gt;&gt; # Build interpolators from GOES grid to model grid
&gt;&gt;&gt; goes_lat, goes_lon = GOES.grid(satellite="goes16", scan_mode="C")
&gt;&gt;&gt; goes_model.build_input_interpolator(goes_lat, goes_lon)
&gt;&gt;&gt; nsrdb_model.build_input_interpolator(goes_lat, goes_lon)
&gt;&gt;&gt;
&gt;&gt;&gt; # Run one GOES forecast step then estimate GHI
&gt;&gt;&gt; y_goes, y_coords = goes_model(x, coords)
&gt;&gt;&gt; ghi_coords = y_coords.copy()
&gt;&gt;&gt; del ghi_coords["lead_time"]
&gt;&gt;&gt; ghi, ghi_coords = nsrdb_model(y_goes.squeeze(2), ghi_coords)

outputs one on a 0.25 degree lat-lon grid (south-pole excluding) [720 x 1440].
